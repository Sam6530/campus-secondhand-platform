## B.2 关键任务与人机交互

本节按A、B、C、D四名成员分别记录一个综合任务，使用统一的“任务与输入—关键交互—调整与产物—核验与引用”顺序。案例依据各成员附件整理，正文篇幅用于说明过程，成员贡献按既定分工共同评价。

### B.2.1 A 业务需求与规则细化

任务与输入：根据A提供的交互附件，AI-A-01—03围绕用户故事与用例、重复操作、交付取消和争议边界展开。输入包括A需求稿、课程功能范围及审阅意见，成果对应需求书第1章、第2章业务部分和第4章。

关键交互：E-A-04保留了“我们是否同时具有用例说明和用户故事，如何保证其差异性”以及“识别为同一次操作的重试后，是返回已有结果，还是重新按新下单检查”等提示。AI分别说明故事与用例的作用，并将重试回执、新交易条件和操作归属分开分析。

调整与产物：据A附件记录，修订涉及故事和用例关联、普通取消与交付登记边界、履约争议适用阶段，以及认证和争议用例的参与者连线。AI-A-03另记录认证重提、旧单沟通、评价公开范围等完善意见的处理，并同步业务规则、权限表及三幅业务图。

核验与引用：A附件列有编号、跨段落一致性及Word/PDF排版检查，相关原始提示、动作和方案处理分别见E-A-04的AI-A-01—03、E-A-05、E-A-10。本节按A供稿呈现其过程，具体业务取舍沿用A对应记录。

### B.2.2 B 分析模型与文档修订

任务与输入：B交互附件记录AI-B-01—03，以A的FR、UC和BR为输入，完成第3章、第5章及领域、活动、状态和顺序模型。初始化时读取共同大纲、B角色skill、协作协议和提交要求。

关键交互：原始任务要求“需要插入的图片应当先编写python脚本生成再插入.md文件中，脚本文件和图片文件应当保留”。后续反馈要求统一撤下状态与对象职责，明确继续履约恢复原阶段，并清楚表达顺序图的失败和返回路径。

调整与产物：据E-B-11记录，AI建立分析类与职责、状态转换及保持记录，生成五幅图的脚本、SVG和PNG；随后合并重复说明，将详细覆盖及自动事件表放入附件，调整图5-2、图5-5并同步文档格式。

核验与引用：B附件记录图源重跑、编号与引用核对、图形目视检查及目录和三格式同步。原始交互见E-B-11的AI-B-01—03，模型与转换关系见E-B-07，修订交接见E-B-12；模型取舍和对应产物按这些记录定位。

### B.2.3 C 交互原型与场景验证

任务与输入：C的AI-C-01/02以A/B用例、BR和ST为依据，完成交互、质量章节及代表性交易闭环原型。任务限定C负责2.5、2.6、第6章、7.3和本人原型及验证材料。

关键交互：C任务原文要求依角色skill完成工作，并保持A/B内容及格式。后续反馈聚焦场景中的故障设置、原意图重试、资料变更及页面可达范围，以及终止提示与实际交付登记的一致表达。

调整与产物：C附件记录原型、22个场景、程序与页面检查脚本的建立，并保留修订过程。AI-C-02补齐逐步调用与页面范围，按登记情况调整终态提示，随后执行程序、页面和文档调用复验。

核验与引用：10月22日C记录22组程序检查、73项断言，8组页面操作和22组调用重放通过。结果适用于本地内存模拟与自动浏览器操作。任务与反馈见E-C-07，逐步输入、状态及截图见E-C-03—05，问题修订见E-C-06。

### B.2.4 D 验收设计与独立核查

任务与输入：D依据共同大纲和D角色skill，维护7.1、7.2、7.4、第8章及AI报告，接收A/B/C同版成果开展阶段交付核验、来源、覆盖和一致性检查，并承担全文核对与材料整理。输入包含业务依据、规则、模型、原型、实际验证记录和各轮审阅反馈。

关键交互：A轮次中，D要求从买方、卖方、访问者、管理员、校园用户和交易当事人六种视角检查日常目标，补查已写内容之外的使用路径。B轮次中，D提出模型与篇幅修订意见，并作出主体成果先接受、余项在本人轮次调整的取舍。C轮次主要核对交互、场景步骤和验证记录。

A轮次核验与初步建议：先复核业务规则、异常边界及图文对应，再用六角色模拟补查认证退回重提、订单沟通、登记后未回应处理、评价可见性等日常路径；账号恢复和重复举报关联作为可选增量讨论。D明确将六项补充意见按建议处理，不计作错误，也不作为合并阻塞项。依据见E-D-03的AI-D-ROLE-01及A六角色讨论汇总。

B轮次核验与初步建议：核对状态定义、物品与订单的占用职责、继续履约恢复原阶段，以及顺序图失败和重试出口；建议合并重复约束、控制新增正文并同步MD、Word、PDF及图源。阶段接受后，M7失败出口和5.2结案叙述等遗留继续记录复核，未按通过自动关闭。依据见E-D-03的AI-D-B-01及E-D-07。

C轮次核验与初步建议：对照A/B规则检查交互与原型，建议明确故障设置、重试操作及页面可达范围，并统一终止提示与交付登记事实。C修订后，D按场景、页面与调用记录复核；见E-C-06/07及E-D-05—07。

调整与产物：智能体辅助形成12组验收标准、24条需求追踪和基线说明，按D反馈核对全文的封面、目录、章节、表题、编号和引用，并整理三份主文档、图源、验证日志及附件索引。D另统筹两视角审查，先独立阅读，再交叉回应，并回查具体原文，将意见归入对应记录。全文核对和材料整理按D的审阅意见迭代，不替代业务规则确认。

核验与引用：D在同字节副本重跑22组程序检查、22组调用及8组页面操作，并新增8组独立反例、45项断言，均通过相应模拟范围检查。关键交互见E-D-03，角色审查见E-D-04，执行结果与逐项复核见E-D-05—07，任务约束和交接见E-D-08—10。

## B.3 角色skill与智能体任务约束

本项目以角色skill作为智能体的直接任务约束。共同大纲规定章节及图表责任，协作协议统一版本、编号和交接，角色skill进一步限定阅读材料、操作范围、输出和核验方式。各成员在任务中提供这些文件，使智能体按共同规则开展工作。

以D角色skill的实际使用为例：任务开始先读取共同大纲、协作协议、提交要求、格式规范及A/B/C同批材料，再组织角色审查、依据核查、反例验证与报告整理。下表将skill中的约束与本轮执行对应。

表B-3 角色skill约束与实际执行

| 约束项 | skill规定及实际执行 |
| --- | --- |
| 任务目标 | 负责A/B/C阶段交付核验、初步建议、验收设计、来源与追踪、独立复核、全文核对、材料整理及AI报告；关联FR、UC、BR、ST和验证记录。 |
| 输入阅读 | 读取共同大纲v3.3、协作协议、D skill、原始提交要求和A/B/C同批输入；登记版本与依据。 |
| 角色与修改范围 | 按职责补充D章节及本人证据；业务规则由A组织，模型由B维护，原型和质量汇编由C维护。 |
| 角色审查方法 | 采用用户/业务管理员和开发/测试两个视角；同版输入、首轮分别审查，再交叉回应与原文核对。 |
| 问题记录 | 给出位置、反例输入、预期、材料表现、依据与影响，按同一编号追加处理及复验。 |
| 输出形式 | 形成验收与追踪、独立复核、AI报告及附件；正文引用实际证据，Word/PDF保持同版。 |
| 结果口径 | 按资料核对、模型阅读、模拟程序及页面操作分别记录方法和结论范围。 |
| 成员责任 | 成员按业务、模型、原型及核验职责作取舍；智能体辅助整理和执行，个人决定关联真实交互。 |
| 执行检查 | 完成D章节及追踪，记录A/B/C轮次核验与建议，开展两视角审查、C检查重跑及8组独立反例，核对全文并整理交付材料。 |
| 任务衔接 | 将独立结果交质量报告引用，模型、规则和验证变更通过编号与版本同步。 |

本例的skill原件位于initialization/skills/req-d-verify/SKILL.md，执行过程见E-D-03—05，约束与结果对应见E-D-08。通过“初始化阅读—职责约束—实际执行—结果核对—材料交接”，skill形成了可检查的任务边界。
