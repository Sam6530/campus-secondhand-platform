# C 场景数据与走查脚本

版本：C-prototype-v1.1，修订日期2026-10-22。所有数据为教学模拟；学生实际观察和D独立复核仍待执行。程序场景和页面可操作范围分别标注，不能把程序通过填写为人工走查通过。

## 开始前与操作约定

1. 用浏览器打开[原型入口](prototype/index.html)。每个SC开始前展开“验证工具与模拟设置”→“重置模拟数据”；初始身份买方甲、I01教材35元，情境正常、通知失败未勾选、无订单。切换身份不会自动切换页面，按步骤点击“我的订单”或“管理台”。
2. 每次普通操作点对应按钮后，填写原因/声明，再点“确认提交”；校验失败弹窗仍开着时，先点“返回”再切换角色或继续其他操作。
3. buyer=买方甲，buyer2=买方乙，seller=卖方，admin=管理员，guest=访问者，unverified=未认证用户。place=确认下单，accept=接受订单，register=登记交付，confirm=确认收到，cancel=申请取消，dispute=申请争议处理，resolve=核查并处置。
4. 原操作重试须保持actor、op、target、data、intent全部一致。页面按钮“查询/重试本人上一操作”按身份找回原请求；身份切换或成功操作会生成新输入框编号，不能用该新编号冒充原意图。不同业务操作用新标识，输入校验失败后修正也用新标识。
5. mode=lost表示业务执行成功但模拟丢响应，pending表示挂起未执行；故障设置对后续操作持续生效。按脚本及时改回正常响应。通知失败为独立复选框，notifications详情需导出JSON查看。
6. 页面不提供的越权请求、隐藏按钮后的非法请求、任意资料修改，只能用程序检查。下表列精确程序输入和预期；页面复做方法另列，二者范围不混写。

## 程序复现方法

在项目根目录运行 `node attachments/C/prototype/verify.cjs`，一次执行全部22场景，逐项打印PV编号，失败时退出码非0。Node无需第三方包。结果保存到[本轮程序结果](verification/revision-20261022/程序验证结果.json)，可用results中的id定位场景；复跑前保留旧结果。

需要单步观察时，在项目根目录运行 `node` 进入交互环境，先执行以下代码，然后逐条执行各SC表格中的调用；每个SC先执行 `p = new Platform()`。这是程序模拟路径，不是浏览器页面操作。

```js
const {Platform} = require("./attachments/C/prototype/core.js");
let p = new Platform();
```

表中的预期来自对应断言及规则；本轮实际值见JSON。场景末尾给出需要核对的结果，不能只看某次返回ok。
