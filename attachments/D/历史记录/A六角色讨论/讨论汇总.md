# A 文档六角色需求覆盖讨论

本轮建议先讨论四件与日常任务相关的事：认证退回后怎样重新提交；订单建立后怎样继续沟通交接；交付登记后对方不回应怎样申请处理；卖方公开信息与评价怎样帮助买方判断可信度。它们主要是已有能力的使用路径与边界需要进一步明确，不应全部当作新增模块。另有账号恢复、重复举报归并等可选增量，是否纳入由实际成员决定。

成员D已于2026年10月15日同意将上述四项和账号恢复、重复举报关联两项纳入对A的反馈，明确要求“不算错误，只能算是建议”。前四项优先讨论，后两项保留可选增量性质，均不计入缺陷数量、不分配V编号、不作为合并的阻塞项。这个决定仅确认建议的纳入及分类，具体业务政策与本期实现范围仍由A组织实际成员决定。

本记录保留候选意见与讨论依据，不代表具体需求已确认、核验通过或真实用户访谈。用户已允许先前四个逻辑与图文讨论点纳入核验；本轮专门补充对未提及任务和不必要要求的检查，暂不讨论缺交附件或其他成员的空白章节。

## 六个视角及其主要贡献

| 视角 | 实际检查侧重 | 汇总保留的主要观察 |
|---|---|---|
| 买方 | 从找物品到判断是否值得交易，再到收货与退出 | 评价和认证信息是否可用于购买判断；等待阶段的可见状态和已有取消入口 |
| 卖方 | 从发布到接单、交接、登记及获得结束结果 | 登记交付后买方不确认的推进渠道；交接沟通是否持续可用 |
| 访问者 | 未登录浏览、决定是否注册、公开信息边界 | 公开详情的字段与身份信息边界；不能从禁止公开认证材料推导昵称也禁止公开 |
| 管理员 | 审核、举报争议、依据和职责范围 | 治理查询如何限定到关联记录；证据不足和责任边界；重复举报可否关联处理 |
| 校园用户 | 未进入某笔交易时的准入和账户使用 | 认证退回重提；账号无法登录时的恢复问题（第二轮由统管提示） |
| 交易当事人 | 双方共同安排交接、等待、结束和争议 | 将已有咨询与订单期间沟通接起来；避免新增规则侵占既有取消权或代确认收货 |

这6个视角不代表新增6种账号或独立权限角色。买方、卖方是校园用户在交易中的身份，交易当事人是与具体订单的关系。

## 建议优先讨论的内容

### 认证退回后可以修改重提吗

**日常任务。** 用户提交了模糊或不合要求的校园材料，被退回后希望修正并再次提交，而不是重新注册账号。

**已有内容。** FR02规定提交身份资料及查询审核结果；UC01-b规定退回显示原因、认证状态不得错误提升。已有“退回”，但没有明确后续修正重提的路径。与物品审核退回后的修改重提相比，认证部分更简略。

**建议最小讨论稿。** 若团队同意，可在UC01-b补充：“认证被退回后，用户可查看原因、修正本人材料并重新提交；重新提交不直接取得认证资格，仍按审核结果生效。”无需为此编造次数、期限，也无需新建完整身份生命周期。

**性质与取舍。** 属已有认证功能的替代路径澄清。若本期确实不允许重提，也应明确退回后的替代办法。A组织实际成员决定，C再落实交互。

### 下单以后双方怎样继续约定和变更交接

**日常任务。** 订单已建立，双方仍需问“明天几点、在哪里、临时改约怎么办”；受限账户也可能还要完成已有交易。

**已有内容。** FR08、UC03-b提供咨询与回复；UC06要求线下交接；BR12保留受限账户旧单处理权，同时禁止发起新咨询。原文并未规定对话关闭，所以不能把“已有对话被关闭”写成现存缺陷。剩下的是：已有咨询能否持续承担订单沟通，以及受限账户能否继续处理该订单相关交流。

**建议最小讨论稿。** 将现有咨询能力与订单期间沟通关联起来，说明当事人怎样继续交流交接安排、受限后哪些旧单交流仍被允许。优先复用现有渠道，不强制新增预约、日程、导航或另一套聊天系统。

**性质与取舍。** 属已有能力的连续使用及权限例外澄清。如果系统只有查看旧记录而没有继续回复能力，是否补充回复就是明确的功能取舍，不能仅靠一句“可查看”替代。A决定边界，B/C/D核对对象、交互与验收。

### 卖方登记交付后买方一直不回应怎么办

**日常任务。** 双方可能已经交货收款，但买方没有回到平台点确认，卖方希望知道可以提醒、申请核查还是继续等待。

**已有内容。** BR08规定只有买方确认才成交；BR09禁止已登记交付后的普通取消；BR15/BR19已有争议及异常终止机制。因此不能宣称“完全没有出口”，也不能忽略待卖方确认阶段买方已有的取消权。

**建议最小讨论稿。** 明确登记交付后不响应是否可以由卖方通过现有争议入口申请处理，是否需要一个轻量提醒入口，以及没有自动超时处理时如何向双方说明当前状态。具体时限如无依据保留待议。

**关键代价。** 若始终不改变“仅买方确认成交”，买方不响应时管理员即使异常终止，也不能把它记成成交；既定统计和物品后续状态会受此影响。这是需要人选择的业务取舍，不能由AI悄悄增加自动收货或管理员代收货来解决。提醒也不能被写成保证对方会回应。

### 评价怎样发挥作用以及公开到什么程度

**日常任务。** 买方不仅想提交自己的评价，也会希望在下单前知道卖方是否通过认证、别人交易后的反馈；访问者关心这些信息是否会暴露身份和隐私。

**已有内容。** FR16、UC08、BR11规定完成后各评价一次；FR07规定公开详情；1.6禁止公开身份材料。评价的提交已覆盖，但谁能阅读评价、公开详情是否显示昵称或认证标记，没有在本轮正文中确定。FR21是管理员统计，不能据此推导普通买方已获卖方成交统计的查看权。

**建议最小讨论稿。** 团队先选定公开详情的可见字段，以及评价仅本人可查、当事人可查还是部分公开。可以考虑只展示昵称和认证标记等有限信息，但这些仍是选项；不默认公开真实姓名、认证材料、联系方式、举报或治理历史，也不直接新增信用分或排行榜。

**性质与取舍。** “把评价用于后续交易判断”具有功能价值，但也涉及访问权限的新决定，不是纯排版修正。隐私与信任之间没有由原文唯一推出的答案。买方和访问者的第二轮方案仍不同，不能写成六角色已达成某个具体公开政策。

## 可选增量不直接算作A的错误

| 候选 | 已有覆盖与额外价值 | 本轮判断 |
|---|---|---|
| 已有账户忘记凭据后的恢复办法 | FR23只明确登录、退出和失效拒绝；恢复有助持续使用原账号 | 第二轮由统管提出、校园用户回应。可选择人工联系处理或后续增量。账户恢复是新增能力，不能声称加一句话就已实现且绝不改变范围 |
| 同一对象多条举报的关联处理 | 单条举报和争议已覆盖；关联可减少重复核查并明确治理统计 | 管理员首轮提出。未见合并不代表系统不能完成现有任务；不必为课程项目增加完整工单流、复杂去重或多岗审批 |
| 管理员按关联订单查看必要材料 | BR14及权限矩阵已有必要范围、授权和留痕；具体关联关系可帮助执行 | 优先视为权限细化。关联咨询不等于自动授权查看全部私聊，不能由AI直接授予访问权 |
| 取消原因向对方可见 | UC07已经要求填写原因，BR16留痕，FR15允许当事人查询订单 | 既有记录的可见性澄清，价值较前述项目低；不能把它误写成“文档没有记录取消原因” |
| 重用历史物品内容再发布 | BR05已有重发及重审，历史版本复制可减少录入 | 操作便利性增强，非业务必需；不能以未写“复制”认定发布闭环缺失 |
| 毕业或资格变化后的持续认证 | 原文只规定当前资格核验及准入 | 暂不作为A缺陷。若团队明确决定本期处理，再分析其范围与旧单影响，不能认定已明确排除或强制加入 |

咨询不预留物品、待卖方确认时可以取消、隐藏或成交记录不进公开交易列表、注册失败反馈原因，原文已经覆盖。把这些转换成用户提示可以改善交互，但不能重复登记为新业务需求。

## 关于不必要或过重的内容

核对后，本轮没有找到证据充分、可以直接建议整项删除的现有核心业务要求。不能为了证明审查完整而硬凑“多余功能”。

**不要把普通举报扩写成完整交易争议程序。** 买方首轮曾认为举报流程过重；交叉回查后撤回。原文已区分一般举报和交易争议，补证也是证据不足时的条件性动作，没有规定所有举报都要经历恢复履约或异常终止。可按情境分段表达，但不应删除最低留痕或声称已存在强制全流程。

**“不能永久悬置”的表达需要可检查边界。** UC10这一目标合理，但没有条件与责任安排时难以判断何时不满足。可讨论由谁跟进、对方不响应时如何处理及何时触发已有出口；无需因此引入任意天数、自动裁决、固定多岗工单或始终由同一个人处理。它是可执行性澄清，不证明管理员治理本身多余。

**重复的规则可以引用，明确的权限不能模糊化。** 原文用例、规则、矩阵和组合表中的部分重复可改为共同引用，以减少同步成本。不能把BR12明确的收藏、咨询限制笼统改成“新增公开互动”：收藏未必公开，措辞反而可能丢失既定权限。

**继续保留**唯一占用、重复操作与竞争保护、交易快照、受限账户旧单权利、登记交付与买方确认分离、管理员不代收货等保障。这些虽偏边界情况，仍直接影响正常交易能否可信地完成。

- 管理员首轮把受限账户能否新发布当作未覆盖，实际BR12已经禁止；第二轮已撤回。
- 管理员首轮绝对化“不得对线下事实作认定”，会架空BR19的核查和归属核实；第二轮撤回。能据哪些材料作平台处置仍可讨论，不能直接取消核查职责。
- 卖方首轮建议成交或撤下后对话只读，属于新提出的策略，原文没有此要求；第二轮已撤回。统管另行纠正：BR05已禁止有有效订单时撤下，不能编造“成交后关闭对话阻断成交前安排”这一时间矛盾。
- 访问者首轮建议只让“未受限”用户公开浏览，与受限账户保留浏览相冲突；第二轮撤回。校园用户第二轮仍用了类似错误措辞，统管不予采用。

- 所谓“确认收到不等于质量满意”不能自动推导完成后的售后权利；应与此前已允许纳入核验的争议适用阶段一并讨论，不在此先承诺救济政策。
