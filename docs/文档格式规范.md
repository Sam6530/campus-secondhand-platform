# 整体文档格式规范

本文件规定排版和表达；具体提交内容、字段、适用条件及负责人必读[提交要求对照](提交要求对照.md)，不以本文件的概述替代。

## 共用格式

- 页面为A4，纵向为主；复杂图确需横向时单独安排。页边距约2厘米，以清晰和整齐为准。
- Word正文使用楷体，建议小四12磅，1.5倍行距；正文及表格样式保持统一。
- 一级标题建议16磅、二级14磅、三级12磅加粗，使用正式标题样式；文档标题建议22磅。正文标题与自动目录对应，目录列三级。
- 表格建议10.5至12磅，1.5倍行距，跨页重复表头，避免行内容被裁切；不能为凑页数缩成难以阅读的小字。
- 封面写实际项目、文档名、版本、日期和成员a、b、c、d；页脚设置页码。尚未发生的确认、活动或结果不写入封面或正文。
- 图按章编号，表按章编号；每幅图有图名、正文引用和解释。图内文字使用清晰中文字体，不强求用楷体损害符号显示。
- 图源和导出同版，图中文字按最终打印尺寸可读；长图可拆分、精简或另页放大，不仅在原尺寸截图中可读。
- 先维护Markdown正文，交付时导出同版Word与PDF；检查目录、页码、图题、跨页表、字体及末章结尾。

大纲另行转为Word时，各级标题采用不同字号；图表配置说明使用红色字体，便于共同评审。正式报告中的图表和解释采用统一正文格式。

## 需求规格说明书

必读skills/共同大纲.md，正文按项目概述、用户需求、领域与数据、规则与权限、行为与状态、质量要求、验收与验证、基线与人机协作八部分组织。按共同确定版本撰写，图表可放附件但正文须标明编号和具体位置。约30页为规划预算，不硬凑页数；完整保留末章论证。图文表用同一术语和编号，配图位置和类型按大纲安排，图的具体业务内容由分析确定。

## 需求分析质量验证报告

报告结构应包括：项目信息与输入版本；关键事实与规则来源和确认状态；模型及状态转换核对；正常、权限、状态、异常场景；原型范围、操作和实际结果；问题处理与复核；实际成员贡献及未完成事项。各项引用同版附件，不重复粘贴整份需求书。

初始化阶段只规定结构，不预填检查数量、通过结果、确认人或活动经历。四类场景和多角色意见分别记录真实执行范围。

## AI智能体使用验证报告

报告结构可包括：使用工具与任务分工；输入、任务约束及版本；实际关键交互与人的决定；执行结果与核验；效果、局限和证据索引。交互记录是否纳入本轮交付，按实际课程要求和本轮约定执行；未保存的记录不事后伪造，截图不得由重建界面冒充真实交互。

## 写作与引用

采用自然、准确的书面中文，业务目标、规则及取舍解释充分，不在正文堆叠agent操作口令。资料来源如实登记取得方式；已确认、待确认和分析推导不混写。参考资料用于支持具体内容，不能将自主设计说成已有校规或把AI回答说成真实访谈。
